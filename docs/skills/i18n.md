# i18n Rules

Đọc khi có UI text, thêm ngôn ngữ, format ngày/số.

## Máy đã ép

- Text trần trong JSX hoặc `placeholder/title/aria-label/alt`: ESLint `i18next/no-literal-string`.
- `t('...')` tĩnh chưa có key trong `locales/en.json`: `src/app/i18n.test.ts` đỏ. Key động qua map (`t(LABELS[x])`) không quét được, tự thêm.

## Cách Dùng

Key là câu tiếng Việt tự nhiên, không phải key kỹ thuật:

```tsx
const { t } = useTranslation();
<Button>{t('Tạo dự án')}</Button>;
t('{{total}} dự án', { total });
```

- Tiếng Việt không có file dịch: thiếu key thì i18next trả lại chính key, nên UI mặc định luôn đúng.
- Tiếng Anh: thêm cặp key/giá trị vào `src/locales/en.json`. Thiếu bản dịch thì hiện tiếng Việt, không vỡ UI.
- Thêm ngôn ngữ mới: thêm vào `LOCALES` trong `lib/locale-storage.ts`, file `locales/<lng>.json`, `resources` trong `app/i18n.ts`, AntD locale trong `app/providers.tsx`, nhãn trong `app/layout/header.tsx`.

## Rule

- Mọi text user thấy đi qua `t()`: label, placeholder, validate message, toast, title modal, aria-label, cột bảng.
- Hằng số label (`PROJECT_STATUS_LABELS`, nav items) giữ tiếng Việt, gọi `t()` lúc render, không gọi `t()` ở module scope.
- Message từ server (`ApiError`) hiện qua `t(getErrorMessage(error))`: có key thì dịch, không thì giữ nguyên.
- Không nối chuỗi để tạo câu; dùng interpolation `{{name}}`.
- Ngày giờ: `dayjs` đã `locale()` theo ngôn ngữ hiện tại trong `app/i18n.ts`.
- Test/E2E chạy với `vi` nên vẫn query theo text tiếng Việt.
